# test1-5：隐式枢纽与 HubNode 实施验收

状态：首轮限定范围已实施，最终确定性与真实 API 验收通过；历史失败完整保留。

## 1. 已完成的修改

- 新增公开 `HubNode(Node)`，不增加 ClassifyNode 等同义类。
- 普通简单 DAG 多入边自动等待并汇总，不再要求用户调用 receive(all)。
- 普通多入多出拥有相同上游集合时共享同一个综合 Info，各下游执行一次。
- Hub 声明 input_count、output_count、input_keys、rules；数量、键和规则在库内校验。
- 通过 inputs[key]、outputs[index] 引用端口；relations 仍为二元组。
- Hub 的完整提示词、固定 out_i 字符串输出、JSON 解析及校验由框架生成和执行。
- Hub 多个输出共用一次模型请求，全部校验成功后创建子 Info 并交给现有调度器。
- 增加 hub_output 来源，记录父 Info、生产节点、生产执行及投递端口；Graph 输出顺序仍由 end 决定。
- 共用现有执行、账户解析、HTTP、取消、期限、日志和清理机制；同步与异步没有第二套 Hub 执行器。
- Node 的声明字段支持子类扩展；Hub 规则进入冻结和回滚，普通 Node 的自定义业务属性仍可删除。
- 更新当前示例、联合验收工具及说明；test1_4 中多余的手工 receive 已移除。

核心文件：[hub.py](../easy_agent/hub.py)、[graph.py](../easy_agent/graph.py)、[node.py](../easy_agent/node.py)、[_api.py](../easy_agent/_api.py)。用户程序：[test1_5.py](test1_5.py)。

## 2. 用户程序与实际结果

“多出一入”按多路上游输出汇合到一个下游理解，对应程序中的 many_to_one。

所有结果均为 `list[Info]`，下表展示各 Info.text 字符串。程序使用数值任务，使数据处理与分支差异可以直接核对。

| 函数／结构 | 实际过程 | 最终输出 | 真实请求 |
| --- | --- | --- | --- |
| one_to_one：1 入 1 出 | 1 → 加一得 2 → 再加一得 3 | `['3']` | 2 |
| one_to_many：1 入 2 出 | 1 → 2；两路分别加一、加二；end 反向排列 | `['4', '3']` | 3 |
| many_to_one：2 入 1 出 | 1、3 分别加一得 2、4，隐式汇总后求和 | `['6']` | 3 |
| many_to_many：普通 2 入 2 出 | 汇总 2、4；一路求和，一路求积；end 为积、和 | `['8', '6']` | 4 |
| hub_many_to_many：显式 2 入 2 出 | Hub 两口分别分配和 6／积 8，下游各加一；end 反向排列 | `['9', '7']` | 5 |

普通多入多出的两条 InfoJoined 记录引用同一个综合 Info ID，验证实际共享；不是生成两个内容相同的 Info。

显式 Hub 的输入按 left／right 端口绑定，不依赖 nodes 或关系的排列；out_0／out_1 对应不同子 Info。验收核对全部端口投递、父链和最终 end 顺序，不仅检查打印值。

文件在 IDE 中选择 conda common 后可直接运行，参数栏留空。默认使用已授权外部 env 文件，每个模型节点各自声明 env_file。

```powershell
& 'D:\anaconda3\envs\common\python.exe' -B -m test.test1_5
```

本轮真实执行由 tests/run_api_round.py 调用上述五个实际业务函数，合计 17 次请求；另有单节点和异步 JSON 输入两个基线请求，最终轮次共 19 次。没有额外重复运行独立真实 main；main 的无参数运行、五行结果及 17 次调用另由受控传输测试验证。

## 4. 故障与并发验证

新增与迁移的回归包括：

- 数量不匹配、非法键／规则、未知端口、方向错误、负数／越界和跨图装配拒绝。
- 装配失败回滚，规则编辑回滚，运行中声明冻结，端口关联替换拒绝。
- 普通汇总不覆盖同名 payload 字段；不同上游集合不混合，相同集合共享综合 Info。
- 同一普通来源填入 Hub 两个命名输入口时保留两次绑定；Info(None) 不算缺失输入。
- 自动生成提示词、输入别名、输出键与端口一致；模型 JSON 字段顺序颠倒仍正确分配。
- 非 JSON、重复键、缺失／额外键、错误类型、围栏、空白值和截断输出拒绝。
- HTTP 401／429／503 不自动重试，原始错误正文不进入异常。
- 上游失败不启动 Hub；Hub 超时／取消后不派生输出。
- 准备端口输出时日志失败不会投递；下游失败取消兄弟任务，不返回部分结果。
- 同图并发运行交错完成，输入、结果、来源及运行 ID 隔离。
- 真实验收工具遇到 Hub 错误停止后续场景；固定输出不符时先检查凭据，再登记实际文本及模型记录。

相关测试：[test_hub.py](../tests/test_hub.py)、[test_boundaries.py](../tests/test_boundaries.py)、[test_live_evidence.py](../tests/test_live_evidence.py)、[test_error_boundary.py](../tests/test_error_boundary.py)。原有 180 项中的一个旧断言已按新默认汇合契约迁移，最终总计 204 项。

## 6. 保留边界与代码检查

- Hub 首版仅作中间节点；每个输入／输出口各绑定一次。
- 拒绝 Hub 串联、同一 Hub 多口到同一目标、端口广播，以及端口关联节点替换。
- 端口结构只读，rules 允许同长度更新，受现有冻结与回滚保护。
- 支持范围内的路径最多包含一次多输入汇合，任意嵌套汇合继续拒绝；条件、循环、动态展开和同一 end 多次产出仍待设计。
- 普通完整 receive(all) 声明兼容进入同一收集路径；没有删除旧条件／循环仍使用的接口。
- JSON 结构正确不保证分类准确、事实正确或对提示注入完全免疫；单个授权账户的测试不构成多提供方兼容性证明。

11 个核心 Python 模块共 3912 行，比本轮前 3583 行净增 329 行。增加端口及契约能力时复用既有执行链，未另建网络客户端、结果缓存或执行入口。静态检查用于补充审查，不宣称代码绝无语义重复或所有工作流已经支持。

完整未决边界继续保存在 [设计问题文件](../v0.3-hubnode-design-issues.md)。
