# Easy Agent v0.1 实现问题清单

更新日期：2026-10-03

本文件列出 `v0.1.md` 无法直接推导出唯一实现、或第一阶段要求与已定义接口之间仍有缺口的事项。代码按“不自行扩充”的原则采用受控错误或最小解释，并在相关位置以问题编号标注。

## V01-001：内置 LLM 节点缺少供应商调用协议

`v0.1.md` 定义了 provider、model、base URL、Prompt、Token 参数和密钥引用，但没有定义：

- 支持哪些供应商协议；
- 请求路径、消息格式和流式格式；
- system/user/assistant 消息如何由 Info、Prompt 和角色组装；
- 响应正文、结构化输出、Token 和错误如何规范化；
- 不同模型不支持 temperature 等参数时的兼容规则。

因此 `Node(...)` 会完成配置解析与校验，但默认 `forward()` 抛出 `UnsupportedFeatureError`。自定义 Node 可正常运行。实现没有擅自假设 OpenAI 兼容协议。

需要后续在架构文档中增加明确的模型适配器协议后，才能实现可工作的内置 LLM 节点。

## V01-002：工具调用循环和审批协议未定义

文档要求工具扩展接口、允许列表和副作用审批，但自定义 Node 的公开签名只有 `forward(info)`，没有受 Graph 管理的工具调用上下文；文档也没有定义模型工具调用格式、审批回调和结果回填方式。

当前实现提供 `easy_agent.tools.Tool` 扩展点，并在 Graph 校验工具名称、允许列表和声明权限。副作用工具会被明确拒绝。工具不会由内置 LLM 自动调用；自定义可信代码直接调用外部资源不可能由该接口拦截。

需要明确 Tool 调用入口、运行上下文和审批状态机。

## V01-003：安全策略对象的公开形态未定义

文档说明 Graph 管理工具、密钥、审批和日志访问，但没有给出 `SecurityPolicy` 的构造接口及权限命名规则。

当前 Graph 只采用最小的 `allowed_tools` 和 `allowed_permissions` 集合，并实行拒绝优先。网络、文件系统、日志查看者身份和多租户边界没有虚构实现。

## V01-004：Schema 协议未定义

文档允许输入/输出 Schema 和 `Info[T]`，但没有指定 Pydantic、dataclass、JSON Schema 或自定义协议。

当前 `input_schema` 与 `output_schema` 只接受 Python 运行时类型，`dict` 与 `list` 对应 Info 的只读映射与元组表示。泛型不执行运行时校验。需要后续确定正式 Schema 协议和版本迁移规则。

## V01-005：输入 Token 预算缺少 tokenizer 与裁剪规则

参数已进入 Node 配置和运行快照，但当前不会自动裁剪正文。文档尚未定义 tokenizer、裁剪顺序、消息保留策略和超限错误语义。静默截断会违背透明原则，因此未实现。

## V01-006：同步 forward 的超时无法在单进程中安全抢占

异步 `forward()` 使用 `asyncio.wait_for` 实施 timeout。同步 `forward()` 在第一阶段直接执行；Python 无法在同一线程中安全终止任意同步代码。

当前不对同步函数伪造强制超时。要实现可中止超时，需要线程或进程后端，并同时定义取消后的副作用状态。

## V01-007：retry 的精确策略没有定义

文档列出重试参数，但没有定义异常分类、退避、抖动和副作用规则。当前 `retry` 解释为额外立即尝试次数；配置、权限、图校验、Info 和未支持功能错误不重试。

涉及副作用的自动重试仍被禁止。后续应将 retry 细化为明确策略。

## V01-008：Node 配置在运行期间被外部直接修改

Graph 会冻结拓扑、路由、接收规则和有效配置快照。自定义 Node 仍是普通 Python 对象，其 `forward()` 可以读取或修改自身及外部可变状态。框架无法复制任意自定义对象并保证语义不变。

当前契约要求用户不要在运行期间修改节点定义。后续可考虑只读配置描述符或显式 `graph.edit()` 生命周期。

## V01-009：max_parallelism 的跨运行范围未定义

当前限制在单次 GraphRun 内生效。同一个 Graph 的多个并发运行之间不共享节点信号量。若它代表外部服务或整个进程级限制，需要定义资源池及限流器的所有权。

## V01-010：结构化汇合只实现文档可验证的最小形式

当前 `receive(mode="all")` 仅支持：一个源节点直接广播到多个分支节点，每个分支节点无条件且仅发送给同一汇合节点。分叉组用于隔离不同激活。

文档明确将任意嵌套循环与复杂动态汇合排除在第一阶段之外，但没有定义“结构化”的完整形式，因此实现采用能静态证明配对关系的最小子集。

## V01-011：日志内容策略与访问主体未形成公开 API

当前默认只保存元数据、哈希、状态和非敏感配置摘要；不保存完整业务正文、Prompt、模型输出和工具参数。日志使用本地 JSONL 文件，并支持 run、node、execution、event 过滤及分页。

内容捕获、脱敏规则、保留期限、调用者身份和独立审计存储未在文档中给出可实现的接口，因此没有扩充。

## V01-012：完整回放和检查点不属于第一阶段

当前可查询已记录事件和 Info 来源，但没有记录驱动执行、实时重执行或崩溃恢复。文档已将这些能力列为逐步扩展，并要求在正文与调度状态完整时才可承诺。

## V01-013：图属性替换后的旧连接需要用户修复

替换或删除 `graph.name` 节点会移除注册，新节点获得新的内部 ID。其他节点仍指向旧 ID，下一次 `validate()` 或运行会给出失效目标错误。

文档要求替换使后续计划失效并重新校验，但没有规定是否自动迁移入边。当前不进行隐式迁移，以保持“源节点声明流向”是唯一关系来源。

## V01-014：本地日志目录没有公开配置接口

文档要求本地日志存储和查询，但没有定义存储路径参数。当前固定写入当前工作目录下的 `.easy_agent/logs/<run_id>.jsonl`，并在 `.gitignore` 中排除 `.easy_agent/`。

若需要部署级持久化，应先定义 TraceStore/AuditStore 的内部协议和受控配置方式，避免把基础设施对象变成普通用户必填项。

## V01-015：配置文件语法采用最小解释

当前 `.env` 支持空行、注释、`export KEY=...`、引号包裹值以及 `KEY=VALUE`。不执行变量插值、命令替换、多行语法或自动父目录搜索。

这是为了保证显式和安全；若要兼容某个 dotenv 方言，应在文档中指定。
