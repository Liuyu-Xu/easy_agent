## 2. 目标用法

以下为下一轮实施目标，尚未替换当前文件。保留run(env_file)以兼容现有回归工具，同时提供无参数默认调用；Python函数参数用于程序内复用，不需要终端传参。

```python
from easy_agent import Graph, Info, Node

ENV_FILE = "D:/code/Python/agent/hello_agent/test.env"


def run(env_file=ENV_FILE) -> Info:
    source = Node(
        env_file=env_file, max_output_tokens=16, timeout=30, max_attempts=1,
        prompt="Reply with exactly CHAIN_A. No other text.",
    )
    target = Node(
        env_file=env_file, max_output_tokens=32, timeout=30, max_attempts=1,
        prompt="If the user message is exactly CHAIN_A, reply TEST1_2_OK. "
               "Otherwise reply TEST1_2_INPUT_ERROR. No other text.",
    )
    graph = Graph()
    graph.involve(nodes=[source, target], relations=[(source, target)], entry=source)
    graph.run(Info("Start test1-2"))
    return graph.result()


if __name__ == "__main__":
    print(run().text)
```

编写要求：

- 只导入Graph、Info、Node，不导入测试辅助模块或异常类。
- 路径只在示例中配置；库中不硬编码本机路径，不读取或改写全局环境变量来搬运密钥。
- 各Node仍可指定不同文件和参数；本示例共享同一文件只为了复用现有授权测试账户。
- 不读取sys.argv，不使用input，不调用argparse，不需要额外run_safe、装饰器、执行器或配置管理类。
- main保护用于防止导入时发出真实请求，保留即可；不要求用户编写退出码。
- 成功直接得到Info；失败自然抛异常。示例展示结果，是否等于TEST1_2_OK由回归工具判定。
- 不通过压缩行数、分号或隐藏节点声明来营造简洁；保留可读的参数与关系。

当前Graph默认timeout为180秒、max_attempts为3，token上限为10000；本次测试要求30秒、1次尝试以及16／32 tokens。当前内置适配器尚未实际重试，也不能据此把max_attempts=1从测试预算中删除。若以后调整库默认值，应单独提出兼容性变更，不夹带在本次简化里。

## 4. 框架应统一承担的保护

### 4.1 保留已有机制，避免再包装一层

继续复用Node配置解析、involve事务、运行配置快照、密钥作用域隔离、适配器协议检查、超时／取消、资源清理及结果生命周期。

Graph.run(info)仍同步返回Info；Graph.result()仍读取最近发起且成功完成的运行。失败不返回None、错误字符串或伪造Info，不自动返回上次成功结果，不增加默认重试，不把SystemExit放进库。

用户仅在业务确实需要补救、降级或交互提示时自行捕获异常，普通串行示例不承担框架级错误归一化。

### 4.2 已有安全处理和待修复路径

内置HTTP适配器已经使用固定错误描述、HTTP状态及from None，避免把HTTP错误正文或原始网络异常直接展示。应沿用这条原则，检查其余框架边界：

| 代码位置 | 当前观察 | 建议 |
| --- | --- | --- |
| [Graph运行边界](../../../easy_agent/graph.py:945) | EasyAgentError(str(exc))并保留原异常链 | 外部异常转为固定安全描述，不插入任意异常正文 |
| [节点执行边界](../../../easy_agent/graph.py:1188) | 普通异常正文插入NodeExecutionError；用户自行抛出的EasyAgentError原样传播 | 区分框架已生成的安全异常和用户扩展抛出的异常，后者不能仅因继承EasyAgentError就被信任 |
| [Schema校验边界](../../../easy_agent/graph.py:1338) | InfoError描述较克制，但from exc仍可展示校验器原始异常及输入 | 默认格式化异常链也要验证，不能只检查最外层str(error) |
| [配置文件读取](../../../easy_agent/config.py:104) | 包装读文件失败时保留底层异常链 | 保留必要的配置定位，不透传文件内容、原异常正文 |
| [日志存储](../../../easy_agent/events.py:29) | 创建、写入、读取错误拼接原异常正文并保留异常链 | 固定安全描述，保留已有LoggingError与run_id |
| [异常基类](../../../easy_agent/errors.py:6) | 已有run_id属性，默认str(error)只显示message | 建议统一显示安全描述及已有run_id，具体文本格式见第7节待定项 |

这说明直接删除脚本try/except可以缩短示例，但还不能作为“全项目异常已安全”的验收结论。先在框架边界统一处理，再验证无捕获运行的表现。

### 4.3 建议的最小内部实现原则

- 复用现有异常类别和run_id；优先使用模块内私有辅助方法，避免新增用户必须了解的类、参数和入口。
- 对框架生成的信息采用固定模板／明确允许的元数据。HTTP状态、已有运行ID可以保留；凭据、Authorization、完整请求／响应、任意异常正文、校验输入不能进入默认异常和框架事件。
- 将用户forward、validator、route等扩展产生的异常视为外部输入；逐条检查相关调用边界。禁止仅用isinstance(error, EasyAgentError)当作安全证明。
- 对已经由库生成的安全异常保持类型和已有run_id；从不受信任异常归一化时抑制默认展示的原始异常链。不要用“对最终字符串替换一个密钥”代替明确边界。
- 不安装全局sys.excepthook，不修改解释器全局日志级别，也不替用户应用吞掉异常。
- 保持异常时的停止、取消、清理、失败状态和结果失效机制。若出现日志故障与运行故障竞争，沿用现有优先级，不借此改变未定稿的诊断协议。
- 框架日志按既有事件白名单记录；测试工具继续独立检查凭据未泄漏。业务Info内容及用户主动print的文本仍由业务选择，本次不自动删改正常结果。
- 对默认Python异常格式进行保证，不声称IDE调试器查看局部变量或任意外部日志插件也被框架控制。
