## 2. 已认可的目标用法

以下目标接口已进入本轮实现。extractor.env和writer.env是配置路径示意，运行时须提供存在且完整的账户文件；不要求创建、复制或提交含真实凭据的新文件。

```python
from easy_agent import Graph, Info, Node

extractor = Node(
    env_file="extractor.env",
    max_output_tokens=512,
    prompt="提取输入中的要点",
)
writer = Node(
    env_file="writer.env",
    max_output_tokens=1024,
    prompt="根据收到的要点撰写内容",
)

graph = Graph()
graph.involve(
    nodes=[extractor, writer],
    relations=[(extractor, writer)],
    entry=extractor,
)

graph.run(Info("待处理内容"))
output = graph.result()
```

接口参数按已认可示意使用小写nodes、relations、entry。nodes是节点成员列表，relations是消息传递方向；列表位置、Python变量名、节点名称均不充当执行顺序。普通终点继续自动收集，output仍是Info。

业务示例应完整显示节点、关系和运行过程。用户不需要实例化配置解析器、调度器、结果管理器，不应手动读取密钥或管理下游调用。

512和1024是业务示意值，不是新增库默认值，也不是本项目真实回归预算。小请求测试仍使用每次最多32输出tokens、一次尝试和每节点30秒尝试期限。

## 4. 对象职责与兼容边界

| 对象 | 目标职责 | 本轮不应混入的职责 |
| --- | --- | --- |
| Node | 声明配置来源、模型和账户引用、prompt、role、请求参数及节点行为 | 修改进程环境；保存公开可导出的明文密钥；替用户调度其他节点 |
| Graph | 接收节点集合、消息关系和入口，校验并生成执行计划，调度和输出Info | 强制所有节点共用同一模型账户；要求用户逐个手工执行节点 |
| Info | 承载输入、节点输出、最终结果及现有来源信息 | 代替配置对象或测试报告字典 |
| 内部配置层 | 解析、冻结和隔离有效配置，记录安全来源信息 | 将多个账户文件合并为一个无作用域的字典 |

Graph.run、Graph.result、__call__和arun沿用已确认契约：run同步返回Info，result读取最近发起运行成功发布的同一个Info；未运行、运行中、失败或取消时报错，旧运行晚完成不能覆盖新结果；不无限缓存历史结果。新增建图接口不允许重写这套生命周期。

旧Graph(env_file=...)和Graph请求默认配置如何兼容，见NIG-D01；本轮文档不授权直接删除旧参数。建议新示例以Node配置为主，旧方式保留明确兼容路径。节点属性注册、send_to、route、receive、graph.edit及运行时修改限制继续保留既有约束。

## 5. Node配置修改要求

### 5.1 配置来源与参数

Node应接受env_file声明，形态与现有Graph文件路径能力一致，具体路径解析时点见NIG-D06。配置在库内部解析；节点实例化和involve均不得发起模型请求。

Node现有model、provider、base_url、api_key_env、temperature、max_output_tokens、timeout等参数继续有效。env文件中的账户字段沿用已支持的LLM_*或EASY_AGENT_*；本指导不新增prompt、token等字段的环境变量语法，token上限在Node构造参数中声明。

Node未填写某参数时必须有可说明的来源，不能仅为使示例通过而偷偷修改模型或默认值。独立文件、显式Node参数、操作系统环境与旧Graph默认值之间的优先级和回退边界须按NIG-D01定稿。

### 5.2 账户与密钥隔离

两个Node的文件可能都使用LLM_API_KEY，但值、模型与地址不同；它们必须解析成两个独立账户。现有按变量名称单独索引secret_values的方式不足以承载此行为，应使内部引用包含节点或配置来源作用域，并同步修改实际请求取值、配置快照、日志审计和导出。

验收不能只检查“有两次调用”：必须验证每个节点的请求地址、model、Authorization和请求预算分别对应自身配置。使用受控传输与合成密钥验证，不输出实际Authorization。

同一账户作用域内，两套账户字段混用仍应明确报错。不同节点合法使用不同字段组，不应因为全图拼接字段而被误判为混合账户。系统环境如何参与各作用域冲突判断，随NIG-D01一起定稿。

禁止将Node文件内容写入os.environ。不同图、同图不同节点和并发运行必须保持隔离，不允许后一个节点解析覆盖前一个节点的密钥。

### 5.3 读取与快照

运行开始时冻结本次有效配置。建议同一次编译或运行对相同规范化文件只读取一次，再按节点选择作用域；不同调用阶段之间不持有永久文件缓存。运行开始后的文件变化不能改变该次调用，后续运行按契约重新解析。

相同文件可以被多个节点引用，配置隔离不意味着必须复制文件或密钥。文件缺失、非法语法、重复键、空值及自定义api_key_env继续有明确的错误与来源记录。env_file新增到节点后，必须纳入定义编辑保护、回滚和运行冻结，不能成为可在运行中偷偷变更的旁路字段。

组装时是否读取配置文件、运行前何时要求完整密钥、相对路径如何固定，见NIG-D06；不得宣称跨多个文件的读取天然具有文件系统原子性。

### 5.4 当前能力限制

max_output_tokens已实际映射到请求输出上限，后续须验证节点独立值。input_token_budget尚未应用，继续如实记录，不在此次Node.env_file修改中顺便实现截断或分词策略。

内置适配器当前仅支持DeepSeek最小非流式文本调用。不同节点拥有独立配置，不自动代表支持其他提供商协议；不增加工具循环、结构化输出、Worker或实际重试能力。

## 6. Graph.involve修改要求

### 6.1 公开形态与关系来源

已认可的调用形态为graph.involve(nodes=[...], relations=[(source, target), ...], entry=node)。source、target和entry使用传入的Node实例，不使用列表下标或变量名字符串猜测节点。

首轮建议relations只表示普通有向消息边；条件路由和all汇合的新语法不在示意范围内，见NIG-D05。关系必须转换成现有节点连线声明，graph.relations继续是派生的只读视图，不新增第二份可独立修改的关系存储。

节点已有独立ID。列表注册需要稳定的内部可读名称供日志、异常和导出使用，但不能要求用户额外编造first、second等Graph属性。命名及可选查找能力见NIG-D02；不得检查Python调用栈来推测变量名称。

新增involve方法必须保持可调用，不能被节点注册或普通属性赋值悄然覆盖。旧图中同名节点的迁移处理与自动名称冲突规则一起登记于NIG-D02；不借此扩大成未经定稿的全部方法保留名政策。

### 6.2 一次装配与失败回滚

建议内部流程：校验参数和归属 → 准备全部节点注册 → 安装关系和入口 → 检查完整图 → 提交定义。可以复用graph.edit的快照、编辑记录和校验机制，但必须核对新加入节点也在回滚范围内，不能只恢复Graph的旧节点字典。

任何失败均不得留下半张图。应恢复或保持节点所有权、内部名称、连接、入口、注册表和编辑状态；一个从未成功装配的外部Node不应因为失败尝试就永久绑定到该Graph。非法关系不得修改无关Graph。

运行中、取消后仍有清理资源、其他执行上下文正在编辑等状态，继续按现有定义保护拒绝装配。参数容器转换可能执行用户代码，必须在实际提交前再次核对可变更条件。

节点重复、边重复、同图节点再次注册和重复调用involve的具体行为见NIG-D03。不得擅自把第二次调用解释为追加、替换或合并。

### 6.3 入口

entry必须指向此次参与装配的有效Node，不能属于其他Graph或游离在nodes列表之外。保留现有入口ID与执行计划机制。

是否允许省略entry及involve的返回值，见NIG-D04。目标示意使用显式entry，不依赖自动按列表首项选入口。旧接口的唯一零入度自动识别规则，不应被此改动无意改变。

### 6.4 装配后自动校验

最低检查项：节点集合非空、身份及归属正确、关系两端在节点集合中、入口有效、所有节点从入口可达，并继续执行已有循环、汇合、结果出口及其他适用校验。结构不合法时在involve返回前报错；不能要求用户再手动调用validate才能发现断开的节点。

此处“连通”定义为：**从指定入口出发，沿有向消息边可到达所有已注册节点。**

```text
A → B → C        入口A：满足可达性
A → B    C       入口A：C不可达，应拒绝
A → B ← C        入口A：C不可达，应拒绝，即使忽略方向后连通
```

不要求所有节点两两互达，普通串行图不需要强连通。条件路由的静态可达只表示存在可能路径，不证明每次运行都会执行所有节点，也不能证明所有业务条件都能终止。

连通性不是完整正确性证明。循环仍遵循显式入口、步数限制与当前支持范围；多入边不能自动改为all汇合；并行多个终点不能默认选最后完成者；运行时零结果／多结果检查继续保留。
