**不允许长期维持现状**：这是一个无声说谎的参数，而且默认值 3 会让人以为已经重试过。

**OI-025 阻塞执行破坏期限归因与并发（本轮实测升级为正确性问题）**

原判断只是"同步 `forward` 拿不到抢占"，实测后发现更严重：**阻塞代码会冻结整个事件循环，让无关分支被误判超时**。

1. 期限 0.05s、同步 `forward` 阻塞 0.5s → 实际 **0.536s** 才返回，抛 `NodeTimeoutError`，编译期**零警告**。
2. `execution="async"`、`max_concurrency=2`，分支 A 在协程内 `time.sleep(0.3)`，分支 B 只 `await asyncio.sleep(0.05)` → B 实测耗时 **0.311s**，即声明的并发被静默串行化。
3. 同一结构下给 A 期限 5s、B 期限 0.1s：B 什么都没做慢，仍在约 0.304s 处被判 **`NodeTimeoutError`**。**这是错误归因：无辜分支因兄弟分支阻塞而失败。**

代码位置：同步路径直接内联调用（[graph.py:1109-1112](../../../easy_agent/graph.py)），阻塞期间协调器无法推进任何其他任务、无法检查任何期限、无法响应取消。

分两步修，第一步不需要 Worker：

- **立即**：编译期识别"同步 forward／声明 async 但可能阻塞"并显式要求承认（`blocking=True`），事件标记 `deadline_enforced=false`；同时把"该节点运行期间会独占事件循环"写进文档与错误消息。
- **完整**：OI-002 的进程 Worker。

证据：[probe_blocking.py](../../../tests/evidence/analysis-2026-10-17/probe_blocking.py)。

**OI-026 `input_token_budget` 接受但不生效**

只记录 `accepted_not_applied`（[config.py:273-274](../../../easy_agent/config.py)）。按 `v0.3.md` 的 C03 这是有意为之，但需要一个公开的"本版不实施"声明位置，而不是藏在 `public_values` 字符串里。

**OI-027 错误消息引用仓库内文档路径**

8 处错误文本写"详见 `v0.3-issues.md`"、"见 Hub 问题文件"等（[graph.py:673](../../../easy_agent/graph.py)、[graph.py:821](../../../easy_agent/graph.py)、[graph.py:1079](../../../easy_agent/graph.py)、[graph.py:1856](../../../easy_agent/graph.py)、[graph.py:1883](../../../easy_agent/graph.py)、[node.py:368](../../../easy_agent/node.py)、[_api.py:85](../../../easy_agent/_api.py)、[_api.py:87](../../../easy_agent/_api.py)）。用 pip 安装的用户手里没有这些 md。需改成稳定的错误码或能力标识（与 OI-010 一起做）。

**OI-028 能力矩阵缺位**

26 处 `UnsupportedFeatureError` 是当前"控制范围"的真实形状，但没有任何一处汇总可见。用户只能靠逐个触发才知道什么不能做。建议在 README 放一张能力矩阵（`v0.3-analysis.md` §7 已有可用的底稿）。

**OI-045 模型类日志事件没有任何公开读取入口（本轮实测新增）**

一次真实单节点运行的日志文件共 12 条事件：`graph` 4、`model` 2、`node` 5、`audit` 1（run_id `4a643de9…`）。但公开 API 只能读到其中 10 条：

- `graph.logs()` 在**不传 `node`** 时把 `category` 静默切成 `"graph"`（[graph.py:2111](../../../easy_agent/graph.py)），只返回 4 条图级事件；
- `graph.audit()` 读 `audit`；
- `node.logs()` 读 `node`（且必须逐个节点调用）；
- **`category="model"` 的 `ModelRequestStarted`／`ModelRequestFinished` 没有任何入口可读**——`logs()` 没有 `category` 参数，用 `event_type="ModelRequestFinished"` 也读不到，因为类别已被强制成 `graph`。

后果：C14 要求"模型节点日志包含响应时间、输入输出 Token、命中率"、C15 要求工具耗时与并发数，这些数据**已经写盘但用户拿不到**。同时 `logs()` 的静默切换极易被误判为"根本没有节点日志"。

修复很小：`logs()` 增加 `category` 参数（默认 `None`＝全部），或新增 `graph.events()` 返回完整有序事件流。这是 C 组里最便宜的一项。
