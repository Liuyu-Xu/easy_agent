## 1. 结论及证据范围

当前项目是 v0.3 的部分实现，尚未达到文档中的执行基础验收要求。问题不仅来自待定参数；已明确的超时停止、冻结原子性、两种工具统一准入、失败编辑无残留等契约仍有可复现偏差。

本轮在 Python 3.13.9、3.10.20 下各运行现有 33 项测试，均通过。下文的定向复现另用 Python 3.13.9 执行，日志放在临时目录，没有加入既有测试套件。测试通过只能证明这些测试已覆盖的行为，不能代替第 18 节全部 T01—T34 验收。

目录没有 Git 历史可供追溯，因此下文区分“当前发现”“本轮新增功能的缺陷”“旧缺口仍未闭合”，不把全部问题称为 v0.3 首次引入的回归。

### A03-001：deadline 没有覆盖成功提交

位置：[graph.py:936](../../../easy_agent/graph.py:936)、[graph.py:954](../../../easy_agent/graph.py:954)。对照 v0.3 第 8.1、8.2 节及 T11—T12。

当前仍依靠 `asyncio.wait_for()` 的返回或异常判断是否超时，没有在成功提交前检查独立的绝对截止时间和运行终态。

两项复现：

- 设置 timeout 为 0.01 秒，异步 forward 等待 10 秒，但捕获 CancelledError 后返回 `Info("late-success")`。实际得到 `late-success`，下游执行，日志出现 NodeSucceeded 和 GraphRunSucceeded，没有 NodeTimedOut。
- 异步 forward 立即完成，输出 Pydantic 校验器耗时 0.05 秒，timeout 同样为 0.01 秒。实际整次调用约 0.057 秒后成功返回。

后果：业务 TimeoutError 的来源区分虽已修复，仍不能声称“异步期限超时一定停止整图”。迟到结果能进入正式输出。

处理方向：按文档先建立 run/attempt 状态及截止时间；监督器确认到期后关闭成功提交和投递入口，所有输出校验后再经过原子提交检查。该契约不依赖先确定清理窗口的默认秒数。

### A03-002：清理状态与运行结果没有分离

位置：[graph.py:295](../../../easy_agent/graph.py:295)、[graph.py:829](../../../easy_agent/graph.py:829)。对照第 8.2、8.4 节及 T13。

复现：取消第一个 arun，节点捕获取消并等待显式释放。在旧任务尚未清理完成时，再对同一 Graph 发起第二次 arun。

实际结果：第二次运行成功；第一个任务仍未结束，第一份日志尚无 GraphRunCancelled / GraphRunFailed。释放第一个节点后才能完成清理。

当前 `_active_runs` 可以保护一部分定义修改，但无法表达 CLEANING / CLEANUP_PENDING，也不会拒绝清理期间的新运行。`gather()` 没有清理期限，不合作任务还可能让取消长期无法返回。

处理方向：先使失败或取消成为可观察终态，并设置独立清理租约；禁止该 Graph 接受新运行直至共享资源清理完毕。清理窗口具体默认值仍可保留为待确认项。

### A03-003：冻结检查与实际赋值不是一个临界区

位置：[node.py:106](../../../easy_agent/node.py:106)、[graph.py:259](../../../easy_agent/graph.py:259)。对照第 4 节第 4—5 条。

`_ensure_definition_mutable()` 在锁内检查后返回；真正的容器转换、字段写入和连接更新在锁外继续执行。

确定性复现：线程给 node.tools 赋一个可控的 list 子类，在其迭代阶段暂停；此时冻结检查已经通过。启动 Graph 并让节点进入执行，再恢复迭代。实际赋值没有抛错，运行中的节点看到 tools 数量从 0 变为 1。

后果：外层 tuple 转换没有消除“检查后开始运行、随后提交修改”的竞争窗口。

处理方向：编辑资格检查、候选校验和最终提交需由同一把定义锁覆盖；运行取得租约和快照也使用该锁。

### A03-004：工具对象的受管理声明仍可变

位置：[node.py:106](../../../easy_agent/node.py:106)、[tools.py:40](../../../easy_agent/tools.py:40)。对照第 4 节第 3 条及 T17。

复现：将 `tool_name="initial"` 的未绑定 Tool 放入 `node.tools`，允许列表只包含 initial。运行开始并等待后，将工具名称改成 changed、side_effect 改成 True，再让节点读取该工具。

实际结果：修改均成功，开始日志的 tools 是 initial，节点读取到 changed 和新的副作用声明。

这是工具名称、权限和副作用等框架声明的冻结问题，不能用“外部客户端不保证线程安全”解释。当前仅断开原 list 的外层别名，未生成冻结工具描述。

处理方向：把这些声明复制到执行计划中的不可变描述，运行中的工具调用和日志共同读取该描述；框架受管对象的声明编辑还应受所属运行租约保护。

### A03-005：默认构造器抹掉已有副作用声明

位置：[tools.py:25](../../../easy_agent/tools.py:25)、[tools.py:38](../../../easy_agent/tools.py:38)。对照第 6.3、14.1 节及 T27。

最小触发：

```python
class WriteTool(Tool):
    side_effect = True

    def forward(self, info):
        return Info("action-executed")
```

`WriteTool()` 之后，类属性仍为 True，但实例属性已经是 False。注册到图后实际返回 action-executed。

原因是新构造器无条件执行 `self.side_effect = side_effect`，而默认参数为 False。既有基于子类属性的工具声明被静默覆盖，副作用拒绝检查因而失效。

处理方向：区分“未显式提供”与 False，保留既有声明或对不支持的声明方式给出明确诊断；不能静默降低副作用级别。

### A03-006：工具放置方式仍改变允许列表规则

位置：[graph.py:1473](../../../easy_agent/graph.py:1473)、[graph.py:1534](../../../easy_agent/graph.py:1534)。对照第 14.1 节及 T27。

复现：`allowed_tools=set()`，工具的 tool_name 为 blocked。

- 注册为独立 Graph Tool：成功执行。
- 使用另一个同类实例放入 node.tools：校验得到 PermissionDeniedError。

这与副作用声明覆盖是独立问题，即使 side_effect 正确也存在。代码已有稳定 tool_name，但只在内部工具循环中检查允许列表。

处理方向：明确两入口使用同一工具描述和准入路径。名称接口仍需决定的部分可以登记，但不能据此把独立入口完全不检查当成满足第 14.1 节。

### A03-007：send_to 失败留下部分更新

位置：[node.py:193](../../../easy_agent/node.py:193)。对照第 13.2 节及 T25。

复现：`graph.a.send_to(graph.b, other_graph.foreign)`。第二个目标导致 OwnershipError，但 graph.a 的下游中已经包含 b。

原因是边遍历边追加，未先完成全部候选校验。调用方看到失败后，图定义却已变化。

处理方向：先在临时集合中验证全部目标，再一次性提交；同类修改接口均应保证失败后原定义不变。

### A03-008：事务回滚遗漏新实例状态

位置：[graph.py:506](../../../easy_agent/graph.py:506)、[graph.py:548](../../../easy_agent/graph.py:548)。对照第 13.2—13.3 节及 T25—T26。

两个复现：

1. 在 graph.edit 中注册临时节点，再删除该属性，最后抛异常。回滚后节点不在图中，但 `candidate.owner is graph` 仍为 True；绑定其他 Graph 会报 OwnershipError。
2. 用带未授权权限的新节点替换有出边的旧节点，并迁移连接。整图校验失败后，旧图恢复、新节点 owner 被清空，但新节点仍带迁移进去的出边 ID。

原因是回滚只枚举当前 `_nodes_by_id` 释放新节点，快照只包含事务开始时已有节点；没有记录本次接触过的所有候选实例及其原始框架状态。

处理方向：跟踪整个事务触及的对象，恢复候选对象的绑定和拓扑声明，或在独立候选定义上验证通过后再安装。

### A03-009：无值 dotenv 项错误地压过高优先级配置

位置：[config.py:74](../../../easy_agent/config.py:74)。对照第 15 节及 T30。

文档明确规定无值 `KEY` 视为未提供，不覆盖有效值。实现则对所有所需键的 None 直接抛 ConfigurationError。

复现：env_file 仅包含无值 `EASY_AGENT_MODEL`，Graph 已显式指定 `model="explicit"`，自定义节点也不需要模型调用；`validate()` 仍失败。

此外，现有 test_v03 的无值项用例恰好断言这种错误行为；测试通过不能证明遵守规格。

处理方向：无值项进入解析后应作为缺失处理，完成优先级解析后，再仅对实际必需配置检查缺失或空字符串。

### A03-010：Pydantic 校验后的业务值未使用

位置：[graph.py:1131](../../../easy_agent/graph.py:1131)。对照第 6.1 节及 T06。

复现：输出模型包含 `count: int = 7`，text 字段 validator 去除两端空白。节点返回 `Info({"text": "  hello  "})`。

实际输出仍为 `{"text": "  hello  "}`，没有模型默认 count，规范化后的 text 也未写入 Info。`model_validate()` 的返回对象被直接丢弃。

后果：路由和下游读取的不是该模型经过验证、规范化并序列化后的值；`extra="ignore"` 等规则也不会反映到实际数据。

处理方向：Schema 边界应取得验证结果，按模型契约转换为 JSON 兼容数据，再构造具有正确来源关系的 Info。仅验证是否抛异常不足以完成适配。

### A03-011：max_attempts 尚不是可工作的重试策略

位置：[graph.py:1048](../../../easy_agent/graph.py:1048)、[test_v03.py:75](../../../tests/test_v03.py:75)。对照第 7 节及 T09—T10。

代码固定 `retryable = False`，因此所有失败均在首次尝试结束，没有任何类别能进入第二次尝试。`retry=n` 的 n+1 换算只体现在配置和日志里。

这不表示所有业务异常都应该重复三次；文档明确禁止重试确定性错误。问题在于允许瞬态适配器错误重试的分支根本不存在，旧重试能力也被整体关闭。

当前名称声称验证总次数的测试仅使用成功的 Identity 节点，并检查配置值为 3，没有验证第二次、第三次或第四次边界。

处理方向：将“参数和弃用映射已实现”与“错误分类、可取消退避和重试执行尚未实现”分别标注；待参数决定后，以受控适配器故障验证确有三次上限。

### A03-012：投递顺序取决于 asyncio.wait 集合

位置：[graph.py:819](../../../easy_agent/graph.py:819)。对照第 9.1、11.2 节。

当前直接遍历 `asyncio.wait()` 返回的 done 集合，然后按此顺序进行投递。

复现：两条立即成功的异步分支汇合，重复 20 次；13 次出现 NodeSucceeded 顺序为 left、right，而随后 InfoDeliveryRequested 顺序为 right、left。这个次数是本轮观察值，不是稳定概率或 API 保证。

当前 all 汇合按声明来源组装，因此上述反转没有导致最终 all 数据次序错误；但不能把这种集合遍历顺序作为未来严格 sequence 的到达事实。同批成功与失败的处理先后也依赖该集合。

处理方向：让完成/接收事件通过协调器拥有的明确顺序队列推进，禁止把无序集合的迭代次序作为业务时序。

## 4. 测试与上一轮结论的修正

- 33 项测试在两个 Python 版本通过属实，但大部分新测试覆盖正常路径或参数表面值。
- 取消测试只包含合作退出的节点，未验证吞取消、延迟清理、新运行准入或迟到提交。
- tools 测试只验证原 list 追加不影响 tuple，没有验证元素声明和跨线程提交窗口。
- 编辑测试验证了旧图恢复，未验证候选节点的绑定及出边是否恢复。
- dotenv 的“字面值”测试只检查密钥引用 resolved，不核对实际解析值；无值项测试还与规格相反。
- Pydantic 测试仅检查字符串数字被拒绝，未检查模型的默认值、规范化、extra 处理和 JSON 输出。
- 并发测试证明了活动峰值为 2，没有证明事件有序、失败后关闭提交或清理有限。

因此上一轮“任务取消和清理”“不可变快照”“原子编辑”“max_attempts 兼容”等完成说明需要分别限定范围，不能据 33 项通过宣布 v0.3 执行基础全部完成。

## 5. 建议优先顺序

1. 先修停止与提交边界，以及清理期间的新运行准入（A03-001—002）。
2. 修定义锁、工具描述冻结、副作用声明和统一允许列表（A03-003—006）。
3. 修失败编辑及候选对象回滚（A03-007—008）。
4. 修配置和 Schema 契约偏差（A03-009—010），同时纠正与规格相反的测试。
5. 在接口细节确定后补完整重试，并在接入 sequence 前修完成事件顺序（A03-011—012）。
6. 按第 18 节逐项建立“已实现 / 已测试 / 待实现 / 真正待决定”的验收对应表，再推进模型、内部工具及 Worker。

本轮没有据这些建议修改代码，也没有为未定参数另设默认值。
