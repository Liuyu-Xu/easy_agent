## 1. 一句话结论

当前仓库是一个**质量不错、边界诚实的执行内核 + 安全边界**，但它还不是一个"agent 编写库"，也还没有比 LangGraph 更易操作：四个目标里，**安全**已经基本立住并有测试证据，**简洁**只完成了一半，**PyTorch 风格**只落到了三个表面特征上，**控制范围广**与目标相反——当前是刻意收窄，并由 26 处 `UnsupportedFeatureError` 显式拒绝。

最关键的三个事实：

1. **`max_attempts` 是空转的公共参数**。默认值是 3、会被校验、会写进 `to_dict()` 和事件里，但执行时 `attempt` 硬编码为 1，没有任何重试循环（[graph.py:1057](../../../easy_agent/graph.py)、[graph.py:1172-1174](../../../easy_agent/graph.py)）。这直接违背已确认要求 **C07/C08（总共三次机会、次数可配置）**。
2. **超时承诺只对 async 节点成立**。同步 `forward` 在协调器线程里被直接调用（[graph.py:1109-1112](../../../easy_agent/graph.py)），180 秒期限只能在函数返回**之后**才被检查，期间整个事件循环被阻塞。Workers 未实现（`multiprocess/hybrid/auto` 全部拒绝，[graph.py:818-822](../../../easy_agent/graph.py)）。
3. **模型完全不能调用工具**。内置适配器在 `has_tools=True` 时直接拒绝（[_api.py:84-85](../../../easy_agent/_api.py)），而任何 `side_effect=True` 的 Tool 在准入阶段就被拒绝（[graph.py:1881-1884](../../../easy_agent/graph.py)）。已确认要求 **C05（模型节点内部调用用户工具）** 尚未实现，能跑通的 Tool 只有纯函数。

## 4. 目标一：比 LangGraph 更易操作 —— 尚未成立

### 4.1 同一件事的两种写法

LangGraph（Python）：

```python
g = StateGraph(State)
g.add_node("a", fn_a); g.add_node("b", fn_b)
g.add_edge(START, "a"); g.add_edge("a", "b"); g.add_edge("b", END)
app = g.compile(); app.invoke({"text": "..."})
```

Easy Agent：

```python
g = Graph()
g.involve(nodes=[a, b], relations=[(a, b)], start=[a], end=[b])
out = g.run([Info("...")])
```

同样 5 行左右。**简洁性并没有被拉开差距**，而差异点全在"取舍"上：

| 维度 | LangGraph | Easy Agent | 判定 |
| --- | --- | --- | --- |
| 编译步骤 | 需要 `compile()` | 自动校验，无编译步骤 | ✅ 更好 |
| 全图共享状态 | 需要先定义 State schema | 无共享状态，Info 点对点 | ✅ 更好（更少概念） |
| 拓扑声明 | 逐条 `add_edge` | `relations` 列表一次给全 | ➖ 平手 |
| 入口／出口 | `START`/`END` 隐式 | 必须显式 `start=[...]`/`end=[...]` | ❌ 更啰嗦 |
| 工具调用 | 一等公民 | **完全不支持** | ❌ 缺失 |
| 条件路由 | 任意 conditional edge | 仅无条件 DAG 或单条有界环 | ❌ 大幅收窄 |
| 流式 | 支持 | 不支持 | ❌ 缺失 |
| 持久化／断点 | checkpointer | 明确不做 | ➖ 平手（本版范围） |
| 文档与上手 | 完整 README、教程 | 根目录**没有 README**，`pyproject` 的 `readme` 指向 676 行设计提案 | ❌ 严重 |

### 4.2 易用性上的四个具体摩擦点

1. **两套互斥的建图 API**。`graph.x = Node()` + `x.send_to(y)` 与 `graph.involve(...)` 并存；后者要求空图、节点不得预先连线（[graph.py:560-576](../../../easy_agent/graph.py)）。用户必须先做选择，且两种风格的报错路径不同。
2. **`start`/`end` 是手工重复声明**。它们在无歧义时完全可以由图推导（零入度／零出度），但 `involve` 强制要求非空列表（[graph.py:567-569](../../../easy_agent/graph.py)），多终点时还必须把全部叶子列全。这是纯粹的用户负担。
3. **没有线性链的语法糖**。90% 的场景是 `a → b → c`，却必须写 `relations=[(a,b),(b,c)]`。PyTorch 用 `nn.Sequential(a, b, c)` 解决了这个问题（见 §5）。
4. **结构化数据读不回来**。`Info.data` 是 `FrozenDict`/`tuple`，内部有 `plain_data()` 负责还原，但**没有导出**（[info.py:234-237](../../../easy_agent/info.py)、[__init__.py:24-43](../../../easy_agent/__init__.py)）。用户要 `json.dumps` 或传给第三方 SDK 时无公开路径，只能自己递归转换。

## 5. 目标二：接近 PyTorch 的操作风格 —— 只实现了三个特征

`v0.1.md` 把"PyTorch 风格"定义为：组件属性注册、构造与执行分离、`forward()` 扩展、可调用对象体验。逐点核对：

| PyTorch 机制 | Easy Agent 对应 | 现状 |
| --- | --- | --- |
| `nn.Module` 子类 + `forward()` | `Node` 子类 + `forward(info)` | ✅ 已实现 |
| 属性赋值自动注册子模块 | `graph.x = Node()` 自动注册 | ✅ 已实现 |
| `module(x)` 触发 hooks 后调 `forward` | `graph.run()` → 统一执行入口 | ✅ 已实现（且比 PyTorch 更严：直接调 `forward` 会因缺少运行上下文被拒绝） |
| `nn.Sequential(a, b, c)` 组合 | **无** | ❌ 只有 `involve(relations=[...])` |
| `nn.ModuleList` 受控容器 | 无 | ❌ |
| `print(model)` 的可读摘要 | **无 `__repr__`** | ❌ 打印出 `<object at 0x...>` |
| `state_dict()` / `load_state_dict()` 往返 | 只有 `to_dict()`，**没有 `from_dict`** | ❌ 单向导出 |
| `register_forward_hook` 扩展点 | 设计中提到"三个扩展点"，无公共 API | ❌ |
| `model.train()` / `model.eval()` | 无 mock/离线模式 | ❌ 任何验证都必须打真实 API |
| 参数／模块遍历（`parameters()`、`named_modules()`） | 无类似入口 | ❌ |

也就是说：PyTorch 之所以"好操作"，主要来自**声明式组合 + 自省 + 可往返的状态**，而这三样恰好都缺失。目前实现的三个特征（子类、属性注册、`__call__`）是最容易的部分。

**最高性价比的补齐（建议 v0.4 第一批）**：

```python
# 1) 组合即表达式：`>>` 生成边，Chain 等价于 nn.Sequential
pipeline = Chain(extract, analyze, summarize)      # 或 extract >> analyze >> summarize
pipeline(Info("..."))                               # 等价 graph.run([...])

# 2) 自省
print(graph)          # 小 ASCII DAG：入口/分支/汇合/终点 + 每节点 model 与 prompt 摘要
graph.summary()       # dict：节点数、边数、入口数、是否有环、有效并发

# 3) 状态往返
spec = graph.to_dict()          # 已有
Graph.from_dict(spec, registry) # 补齐，PyTorch 的 state_dict 对称性

# 4) 离线判定
graph.eval(mock={"a": "固定输出"})  # 或 Node(reply="...")，让示例与 CI 不依赖真实密钥
```

`graph.eval(mock=...)` 这一条对"易操作"的边际收益最大：当前 `test/` 的七个公开示例**全部**硬编码了外部 `test.env` 路径（例如 [test/test1_5.py:5](../../../test/test1_5.py)），任何人 clone 下来都跑不通，这本身就是"比 LangGraph 更好用"的反例。

## 6. 目标三：安全 —— 最强项，但有两处承诺与实现不一致

### 6.1 已经立住的边界（有代码与测试支撑）

| 出站地址强制 HTTPS（本地回环例外）、禁重定向、禁 URL 内认证信息 | [_api.py:53-70](../../../easy_agent/_api.py) | 防密钥被转发到任意主机 |

| dotenv 禁插值、非法行/重复键即失败 | [config.py:115-157](../../../easy_agent/config.py) | 有明确迁移诊断 |

这是本项目真正的护城河，LangGraph 在同层级上并未提供（尤其是错误文本边界与密钥引用审计）。

### 6.2 两处"承诺 > 实现"

- **同步节点的期限**。文档 §8.3 说需要可终止 Worker，代码注释也承认（[graph.py:1110-1112](../../../easy_agent/graph.py)），但对用户而言，`timeout=180` 是一个**没有生效的公共参数**——写一个同步 `forward` 的人不会收到任何警告。
- **`max_attempts` 的语义**。文档说"总共三次机会"，代码只有一次（[graph.py:1057](../../../easy_agent/graph.py)、[graph.py:1172-1174](../../../easy_agent/graph.py)）。测试也把这个行为固化成了断言（`test_unclassified_adapter_like_failure_still_has_one_attempt`），所以它是**已知并接受**的偏差，而不是缺陷遗漏——但对用户仍然是误导性 API。

## 8. 缺陷与风险清单（按优先级）

### P0 — 会让用户对契约产生错误预期

**P0-1 `max_attempts` 完全空转。**
`attempt = 1` 硬编码，`_NodePlan.effective_config` 里带着 `max_attempts` 却无人读取。改进方向二选一：(a) 真正实现重试内核；(b) 在所有公开处标注"仅一次实际尝试"，并在 `to_dict()`/事件里区分"配置值"与"有效值"。**不可长期维持现状**，因为默认值 3 已经在误导。

**P0-2 同步 `forward` 使期限承诺失效且无提示。**
[graph.py:1109-1112](../../../easy_agent/graph.py) 直接同步调用。建议在编译阶段拦截：`iscoroutinefunction(forward) == False` 且 `timeout` 生效时，要求显式声明（如 `blocking=True` 或 `execution="thread"`），并给出"该节点不享受期限抢占"的明确诊断。这比等 Worker 落地更快，且符合项目"宁可拒绝也不假装"的风格。

**P0-3 "agent 库"的核心能力缺失。**
内置模型不能调工具（[_api.py:85](../../../easy_agent/_api.py)），副作用工具一律拒绝（[graph.py:1882-1884](../../../easy_agent/graph.py)），模型返回 `tool_calls` 也拒绝。**这是目标与实现之间最大的单点差距**：没有工具循环，`Node` 只是"一次模型调用"，项目定位中的"agent"部分尚未开始。

### P1 — 正确性或可用性隐患

**P1-1 `topology_hash` 不可复现。**
[graph.py:1785-1788](../../../easy_agent/graph.py) 用 `self.to_dict()` 算哈希，而 `to_dict()` 包含 Graph 的 `uuid4` id、节点 `uuid4` id 与 `log_dir` 绝对路径（[graph.py:2206-2224](../../../easy_agent/graph.py)）。同一份拓扑在两个进程里哈希必然不同，因此它**不能**用于比对、缓存或回归基线。若保留该字段，应只对结构＋有效配置哈希，排除实例 id 与路径。

**P1-2 日志不可关闭，且写盘失败会让成功的运行业务变成失败。**
默认 `log_dir = cwd/.easy_agent/logs`（[graph.py:238-243](../../../easy_agent/graph.py)），`log_dir=None` 也走默认值，没有"关闭"语义。每个事件都 `open/write/close` 一次（[events.py:81-87](../../../easy_agent/events.py)），并且写失败会抛 `LoggingError` 让本次运行失败（有测试固化该行为）。后果有二：一是工作树里已堆积约 2000 个 `.jsonl`；二是把业务可用性绑在了磁盘上。建议至少：区分 `audit`（必须成功）与 `trace`（可降级）两类事件，并提供 `log_dir=False`／内存后端。

**P1-3 结构化 Info 无公开还原入口。**
`plain_data()` 未导出（[info.py:234](../../../easy_agent/info.py)）。用户拿 `info.data` 去做序列化或传给第三方 SDK 时无处可去。建议以 `Info.to_plain()` 或公开导出的 `plain_data()` 补齐。

**P1-4 没有 `from_dict()`／没有 `__repr__`。**
只有一个方向的状态导出，且对象打印不可读。这两点直接削弱 PyTorch 式手感，实现成本极低。

### P2 — 工程与仓库卫生

**P2-1 根目录没有 README，`pyproject` 指向设计提案。**
`readme = "v0.3.md"`（[pyproject.toml:9](../../../pyproject.toml)）。任何人第一次接触拿到的是一份 676 行中文提案，而不是"三分钟跑起来一个两节点图"。缺 `LICENSE`、缺 `CHANGELOG`、缺用法教程。

**P2-2 没有版本控制。**
`.git/HEAD` 不存在。全部历史以"日期 + 版本号 markdown"的方式保存，这也是文档里反复出现"目录没有可用 Git 历史，不能据此断言缺陷来源"的原因。对一个宣称安全的库，不可审计的变更历史是结构性风险。

**P2-3 没有静态检查与 CI。**
`pyproject.toml` 只有 14 行：无 `[tool.ruff]`、`[tool.mypy]`、`[tool.pytest]`、无 CI 配置。`requires-python = ">=3.10"` 的双版本兼容只靠人工在两套 Python 上各跑一遍。

**P2-4 测试入口与主流生态脱节。**
用 `unittest discover`；`tests/` 里没有 `conftest.py`，`pytest` 直接跑会得到另一套行为。建议统一到 pytest（`unittest` 用例可被 pytest 直接收集，风险很低）。

### P3 — 小问题

**P3-1 纯 Python 图也会解析模型账户。**
`_ConfigResolver.resolve()` 对**每个**节点调用，非 scoped 分支必然进入 `_legacy_account()` → `select_env_keys()`（[config.py:218-236](../../../easy_agent/config.py)、[config.py:249](../../../easy_agent/config.py)），因此在 env 文件里同时存在 `EASY_AGENT_*` 与 `LLM_*` 时，一个完全不用模型的图也会因配置冲突失败。

**P3-2 `max_steps` 超限时缺少节点级失败事件。**
`state.consume_step()` 在 `try` 之前调用（[graph.py:1056](../../../easy_agent/graph.py)），抛错时尚未写 `NodeAttemptStarted`，也没有对应的 `NodeFailed`，日志上会看到一次"凭空消失"的任务。

**P3-3 `logs()` 默认取 `_last_run_id`。**
并发运行时该字段会被最后一次运行覆盖，查询目标不确定。建议并发场景强制显式 `run_id`。

## 9. 建议路线（v0.4）

按"收益／成本"排序，而不是按文档章节顺序。前三项都是**让承诺与实现一致**，属于必须先做的诚实性工作。

### 阶段 0：交付面（约 1 天量级，收益最大）

1. 写 `README.md`：安装、三节点示例、无密钥的 mock 示例、与 LangGraph 的定位差异、当前能力矩阵（把 §7 的 26 项拒绝做成一张表）。
2. `pyproject.toml` 的 `readme` 改指 `README.md`；补 `LICENSE`、`[project.urls]`、`[tool.ruff]`、`[tool.mypy]`、pytest 配置。
3. `git init` + 首次提交 + `.gitignore` 已就绪；后续每轮整改用 commit 串起来，替代"日期文档"承担溯源职责。
4. `tests/` 增加 CI 工作流：Python 3.10 / 3.13 矩阵，仅跑确定性用例。

### 阶段 1：诚实性（让 API 不再撒谎）

1. **重试内核**：`_execute_item` 外部包一层 `for attempt in range(1, max_attempts + 1)`，`active_attempts`、`_Outcome.attempt`、事件字段都已预留，改造面很小。首版只需支持"适配器标记的可重试错误 + 有界退避"，其余错误仍立即失败。
2. **同步节点显式降级**：编译期拒绝"同步 `forward` + 无 Worker"，或接受但要求 `blocking=True` 并在事件里标记 `deadline_enforced=false`。
3. **`topology_hash` 重建**：只哈希结构（节点名、边、route/receive 规则、schema 名），排除 uuid 与路径。
4. **`max_attempts` 语义对齐文档**：实现前，先在 `to_dict()` 与事件里区分 `max_attempts`（配置）与 `attempts_used`（实际）。

### 阶段 2：成为 agent 库（最大的目标缺口）

1. **模型内部工具循环**：`Node(tools=[...])` 走同一执行入口，工具是父尝试的子活动；顺序执行，不占图名额。这是 C05。
2. **副作用准入降级为可配置**：`side_effect=True` 从"永久拒绝"改为"需要显式 `allow_side_effects=True` + 逐次审计事件"。副作用永久禁止等于没有 agent。
3. **结构化输出**：复用已有的 `_validate_schema`，把内置适配器的 `output_schema` 从 `{None, str}` 放开到 Pydantic v2。
4. **运行上下文**：`node.runtime`（只读 run_id／轮次／剩余期限／`record_step()`）。这是 P03-008 的阻塞项，也是日志指标落地的前提。

### 阶段 3：PyTorch 手感

1. `__repr__` / `summary()`；2. `from_dict()`；3. `Chain` / `>>` 组合算子；4. `graph.eval(mock=...)` 离线模式；5. hooks（`on_node_start` / `on_node_end`）。

### 阶段 4：控制范围

`receive(mode="sequence")` 时序会话 → 流式 → Worker 后端 → 清理窗口。这些是 P03-003/004 的阻塞项，成本最高，放在手感修完之后。

### 一个反建议

**不要再增加设计文档的篇幅。** 当前 `v0.3.md`（676 行）与 30+ 个 markdown 的体量，已经超过实现本身的可验证速度：`max_attempts` 写了三节规格、代码一行没生效；`sequence` 会话写了整章、代码是一句拒绝。"控制范围广"应该通过**减少被拒绝项**来达成，而不是通过增加规格条目。建议 v0.4 只写一份不超过 150 行的范围声明 + 一张能力矩阵，其余用代码与测试表达。
