# 当前设计与接口契约

更新：2026-10-19。本文描述当前实际支持的行为；未开放的扩展统一登记在 [问题清单](issues.md)。历史决策与完整旧编号见 [归档索引](archive/README.md)。

## 1. 公开运行接口

- `Graph.involve(nodes=..., relations=..., start=..., end=...)`：只在空图装配一次，返回 None；失败完整回滚。
- `nodes` 为 Node 实例列表；普通关系为 `(source, target)`，端口关系使用 Hub 的端口引用。
- `start`、`end` 为非空 Node 列表，分别定义输入和结果顺序；运行要求输入是 `list[Info]`，数量与 start 一致。
- `run(inputs)` 同步返回本次 `list[Info]`；`await arun(inputs)` 走同一内核；`__call__` 是 run 的直接兼容别名。
- `result()`、`entry` 已移除；不缓存最近成功输出。运行中、失败和并发结果均由各调用的返回值或异常表示。
- `run`、`arun`、`involve` 为保留方法名。自动名称为 `node_<完整ID>`，关系和边界使用实例，不依赖字符串名称查找。

图须通过所有权、重复节点/边、入口可达性和出口完整性检查。显式 start/end 当前只支持无条件无环图，必须覆盖全部零入度节点和终点；每个 end 恰好产出一次，不用 None 填空，也不覆盖重复结果。

旧属性注册、`send_to`、`route`、`receive(mode="all")` 与编辑事务仍保留。它们不能在 involve 装配前预先给节点连线，也不能绕过当前拓扑限制。旧条件/有限单路径循环与新边界扩展的迁移尚未定稿，不能按“减少方法数量”直接删除。

## 2. Node 配置和 Info 数据

Node 可配置 `env_file`、模型账户引用、prompt/role、温度、输出预算、timeout、max_attempts、Schema 和 tools 等。Node 级 env 文件的路径在设置时固定为绝对路径并检查存在，装配时验证，运行时重新读取并冻结；同一轮不在节点执行过程中动态改账户。

| 账户作用域 | 规则 |
| --- | --- |
| Node 显式 env_file | 仅 Node 显式参数和该文件决定账户；model、base_url、所选密钥须完整；不从系统环境或 Graph 补缺 |
| Node 未指定文件 | 保留 Node 显式值 → Graph 显式值 → 系统环境 → Graph 文件 → 默认值的原规则 |
| 数值执行参数 | Node 显式值优先，未指定时可继承 Graph 默认值 |
| 配置组 | 兼容 LLM_* 与 EASY_AGENT_*；同一账户作用域同时出现两组账户字段即失败；共享 provider 不独立构成第二组 |

密钥只在本地运行进程中读取，不进入导出、事件或错误正文。导出保留文件路径和密钥引用，不能把引用名当作密钥值。仅使用模型账户，无关 Tavily 账户不属于本项目测试范围。

Info 接受 JSON 兼容数据，冻结字典和序列，拒绝非字符串键及非有限浮点数，保留内容哈希、父来源和运行身份。普通节点 `forward(info)` 必须返回 Info。输入/输出 Schema 复用库内验证；输入 Schema 若改变内容会拒绝执行，变换后的来源协议仍待定。输出可以按既有 Schema 规则规范化。

## 3. 普通多输入、多输出与 Hub

普通 DAG 多输入节点自动等待全部直接上游，按稳定来源顺序形成包含各路数据的综合 Info。相同输入组可复用同一综合 Info，再向下游逐一传递；合并顺序不取决于完成顺序。它只负责数据汇总与广播，不执行语义分类。

```python
hub = HubNode(
    env_file=account,
    input_count=2,
    output_count=2,
    input_keys=["requirements", "materials"],
    rules=["提取需求并形成行动清单", "整理材料并指出缺失信息"],
)
relations = [
    (requirements_node, hub.inputs["requirements"]),
    (materials_node, hub.inputs["materials"]),
    (hub.outputs[0], action_node),
    (hub.outputs[1], material_node),
]
```

这是装配关系的片段，节点与 account 由应用提供。库根据端口数、输入键和规则自动生成提示词，要求模型返回精确的 out_i → 非空字符串对象，拒绝重复键、额外/缺失字段和非法数值；全部端口校验后才投递子 Info。

当前每个端口须绑定一次。Hub 只作为中间节点，不支持 Hub 串联、一个输出端口广播至多个目标、同一 Hub 多个输出连接同一目标、动态端口及每端口任意类型 Schema。每条支持的路径最多一次多输入汇合；嵌套汇合明确拒绝。条件分支空位、循环配对等语义仍在 OI-011/012 中。

## 4. 工具统一边界

`Node(tools=[...])` 的内部工具是父尝试的子活动，不是额外图节点，不触发路由或下游投递。工具须在 Graph 的 allowed_tools 中，required_permissions 必须被授权；side_effect=True 当前拒绝。

| 工具类型 | 契约 |
| --- | --- |
| 普通函数 | 编译时解析并冻结签名、类型和必填性；模型声明与本地验证复用同一参数契约，不在运行时重新猜测类型 |
| 参数类型 | str/int/float/bool/list/dict 及 Optional；不支持任意泛型或位置专用、可变参数；允许具名参数和关键字专用参数 |
| 数值与空值 | JSON Schema number 接受整数或浮点数，排除 bool；Optional 同时在声明和执行中允许 null；未传参数与显式 null 分别处理；不隐式转换数据 |
| Tool 实例 | 继续遵循 Info → Info；内部调用输入须接受 JSON 对象，支持 None、dict 或现有对象型模型 Schema；不兼容的输入 Schema 在编译时拒绝；输出 Schema 同样执行 |
| 参数 JSON | Hub 和工具共用严格对象解析：拒绝重复键、NaN/Infinity、溢出为非有限数的数值及非法顶层形态 |
| 失败回填 | 未知工具、非法参数、普通工具错误、不可序列化结果回填安全分类；准入和框架停止错误仍中止尝试；不回显原异常正文 |

工具响应必须以 tool_calls 正常结束，最终文本必须以 stop 正常结束；截断、中止或消息形态与结束原因矛盾时，在执行工具前失败。成功事件使用实际已校验的结束原因。

同一尝试的各模型轮次共享绝对 deadline 和输出预算。每轮发送剩余额度，按该额度校验已报告用量；超额不能执行本轮工具或发布成功。用量恰好耗尽时，允许最终文本，拒绝需继续请求的工具轮；工具续轮缺 usage 也失败。

重试会重新执行此前已成功的工具，因此目前只允许无副作用工具。框架不会把调用者的无副作用声明变成 Python 沙箱或外部幂等保证。

## 5. 调度、重试和清理

- 同步和异步业务共用调度器；同步 forward 与同步工具使用单次运行的跟踪线程池，避免阻塞事件循环。
- 重试只针对适配器明确标记的瞬态失败，包括指定 HTTP 状态及传输错误；确定性协议/Schema 错误和框架期限不重试。
- max_attempts 是总尝试次数。重试保持执行身份、递增 attempt，每次尝试重新计 deadline 和输出预算。
- 退避不占并发名额；协调器同时响应任务完成和最近重试到期，避免兄弟任务阻塞重试。
- 失败/取消关闭结果提交与消息投递。阻塞工作按运行、执行、尝试归属跟踪；线程真正退出前继续持有定义租约。
- NodeTimedOut 如实记录是否仍有该尝试的阻塞线程；线程不能被强制终止。模型 deadline、调度和清理不是进程隔离承诺。

**仍待定的步数口径（OI-057）**：本轮保留现有实现，max_steps 按节点尝试计次，内部工具另有私有 64 轮上限；内部工具不计入 max_steps。这与历史指导不同，未确定新口径前不宣称 max_steps 限制了所有工具操作。

日志现有公开入口分别提供 graph/node/audit；模型类别事件已写盘，但统一公开查询仍待 OI-045。本轮真实回归通过内部验收接口读取，不代表该公开缺口已修。

## 6. 当前修改原则

代码保留唯一运行内核和必要兼容入口。共享参数契约、严格 JSON 解码和阻塞任务归属，减少同一规则的重复解释；不以删除异常、锁和清理分支换取表面行数减少。全局编译锁、深图递归和日志生命周期仍是开放问题。

公开行为、能力边界和未决事项分别在本文及问题清单维护；本轮代码与测试结果见 [变更记录](changes.md)，测试规程见 [API 测试规则](../v0.3-api-minimal.md)。
